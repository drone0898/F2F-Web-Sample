## 1. 게임 개요

### 1.1 핵심 컨셉

| 항목 | 내용 |
|-----|------|
| **장르** | 방치형 관조 시뮬레이션 |
| **플랫폼** | 웹 (PC/모바일 브라우저) |
| **접속 형태** | 다중접속 (세션당 최대 20명) |
| **플레이 스타일** | 순수 관조형 + 반방치 (하루 1-2회 개입) |
| **핵심 경험** | "신"이 되어 세계의 변화를 지켜보고, 가끔 개입하여 영향을 미침 |

### 1.2 한 줄 요약

> **"여러 신들이 함께 지켜보는 세계, 당신의 한마디가 세계를 바꾼다"**

## 3. F2F 엔진 확장: Object Generator

### 3.1 역할

F2F 엔진에 **콘텐츠 생성 모듈** 추가:

| 기능 | 입력 | 출력 |
|-----|-----|------|
| **개입 해석** | 신의 개입 텍스트 (200자) + 창세기 + 현재 상태 | 영향 결정 (어떤 변화가 일어날지) |
| **상태 생성** | 오브젝트 + 영향 설명 | 새로운 상태 번호 + 상태 설명 텍스트 |
| **오브젝트 생성** | 개입 키워드 + 창세기 | 새로운 maked object (이름, 초기 상태, 스프라이트 힌트) |
| **자동진행** | 현재 세션 스냅샷 + 창세기 | 시간 경과에 따른 자연스러운 변화 |

### 3.2 API 설계 (추상)

```
POST /v1/genesis/interpret
Request:
{
  "session_id": "...",
  "genesis": "하늘섬의 실험실...",      // 창세기
  "intervention": "푸른 비가 내린다",    // 신의 개입
  "current_objects": [                  // 현재 오브젝트들
    { "id": "obj_1", "name": "하늘 풀", "state": 0, "state_desc": "..." }
  ]
}

Response:
{
  "effects": [
    {
      "type": "state_change",
      "target_id": "obj_1",
      "new_state": 1,
      "new_state_desc": "푸른 빗물에 젖은 하늘 풀. 줄기 끝이 파랗게 빛난다."
    },
    {
      "type": "create_object",
      "object": {
        "name": "물방울 정령",
        "state": 0,
        "state_desc": "방울 형태의 작은 생명체. 주위 온도를 낮추는 힘을 지닌다.",
        "sprite_hint": "water_spirit_small"
      }
    }
  ],
  "narrative": "푸른 비가 하늘섬에 내리기 시작했다. 하늘 풀이 빗물을 머금자..."
}
```

```
POST /v1/genesis/auto-progress
Request:
{
  "session_id": "...",
  "genesis": "...",
  "elapsed_hours": 6,
  "current_objects": [...]
}

Response:
{
  "effects": [...],
  "narrative": "6시간이 흘렀다. 해가 기울며..."
}
```

### 3.3 저장 구조 (게임 서버)

```
┌─────────────────────────────────────┐
│            Origin Pool              │
│  (사전 정의된 기본 오브젝트)          │
│  - 떡갈나무, 바위, 풀, 물, 불 등      │
│  - 관리자가 수동 등록                │
└─────────────────────────────────────┘

┌─────────────────────────────────────┐
│            Maked Pool               │
│  (플레이어 개입으로 생성된 오브젝트)   │
│  - 물방울 정령, 구름 고래 등          │
│  - F2F 엔진이 생성, 게임 서버 저장    │
│  - 다른 세션에서 재사용 가능          │
└─────────────────────────────────────┘

┌─────────────────────────────────────┐
│          Session State              │
│  - session_id                       │
│  - genesis (창세기)                  │
│  - objects[] (현재 오브젝트 + 상태)   │
│  - participants[] (참가 신들)        │
│  - history[] (개입/변화 히스토리)     │
└─────────────────────────────────────┘
```

## 4. 게임 루프

### 4.1 전체 흐름

```
[세션 생성] → [신 참가] → [관조] ←→ [개입] → [F2F 해석] → [상태 변화] → [브로드캐스트]
                           ↑                                              │
                           └──────────── [자동진행 (주기적)] ←─────────────┘
```

### 4.2 시간 흐름

| 이벤트 | 주기 | 설명 |
|-------|-----|------|
| **자동진행** | 1-6시간 | F2F 엔진이 시간 경과에 따른 자연스러운 변화 생성 |
| **개입 가능** | 상시 | 신은 언제든 개입 가능 (단, 쿨타임 or 횟수 제한) |
| **세션 종료** | 7-30일 | 세션의 수명, 이후 아카이브 |

### 4.3 반방치 설계

```
[접속 안 해도]
- 자동진행으로 세계가 계속 변화
- 다른 신들의 개입으로 변화
- 돌아왔을 때 "그동안의 변화" 요약 제공

[접속하면]
- 실시간으로 변화 관찰
- 개입 입력 가능
- 다른 신들의 개입 실시간 확인
```

## 5. 다중접속 설계

### 5.1 실시간 동기화

```
┌──────────┐    WebSocket     ┌──────────┐
│  신 A    │ ◄──────────────► │          │
├──────────┤                  │  게임    │
│  신 B    │ ◄──────────────► │  서버    │
├──────────┤                  │          │
│  신 C    │ ◄──────────────► │          │
└──────────┘                  └──────────┘

브로드캐스트 이벤트:
- 새로운 개입 발생
- 오브젝트 상태 변화
- 새 오브젝트 탄생
- 자동진행 결과
- 신 입장/퇴장
```

### 5.2 동시 개입 처리

```
[신 A 개입] ─┐
             ├─► [큐] ─► [순차 처리] ─► [브로드캐스트]
[신 B 개입] ─┘

- 개입은 큐에 쌓여 순차 처리
- 처리 결과는 모든 참가자에게 브로드캐스트
- 처리 중에는 해당 신에게 "처리 중..." 표시
```

### 5.3 세션 참가

| 단계 | 설명 |
|-----|------|
| 1. 로비 | 진행 중인 세션 목록 (창세기 미리보기) |
| 2. 선택 | 마음에 드는 세션 선택 또는 랜덤 입장 |
| 3. 관조 | 세션 화면 진입, 현재 상태 로드 |
| 4. 개입 | 원할 때 개입 입력 |

## 11. 결정된 사항

### 11.1 스프라이트 생성: AI 픽셀 이미지 생성

```
[F2F Object Generator]
     │
     ▼
{ name: "물방울 정령", sprite_hint: "작은 물방울 형태, 투명, 파란 빛" }
     │
     ▼
[AI Image Generator] ──► 32x32 픽셀 스프라이트 생성
     │
     ▼
[게임 서버 저장] ──► maked pool에 이미지 URL 포함
```

| 항목 | 설계 |
|-----|------|
| **해상도** | 32x32 또는 64x64 픽셀 |
| **스타일** | 픽셀 아트 (일관된 팔레트) |
| **생성 시점** | 오브젝트 최초 생성 시 1회 |
| **저장** | CDN/스토리지에 저장, URL로 참조 |
| **캐싱** | maked pool에 저장되어 재사용 |

### 11.2 세션 수명: 7일 ~ 365일

| 항목 | 설계 |
|-----|------|
| **최소** | 7일 |
| **최대** | 365일 |
| **설정 주체** | 창조자가 세션 생성 시 선택 |
| **종료 후** | 아카이브 (읽기 전용으로 보존) |
| **연장** | 유료 재화로 연장 가능 (옵션) |

```
세션 생성 시:
┌─────────────────────────────┐
│  세션 수명 선택              │
│  ○ 7일 (단기 실험)          │
│  ○ 30일 (기본)              │
│  ○ 90일 (장기)              │
│  ○ 365일 (에픽) [프리미엄]   │
└─────────────────────────────┘
```

### 11.3 개입 제한: 하루 10회 + 쿨타임

| 항목 | 설계 |
|-----|------|
| **일일 한도** | 10회/일 (00:00 UTC 리셋) |
| **쿨타임** | 개입 후 10분 대기 |
| **추가 획득** | 광고 시청 시 +1회 (일일 3회 한도) |
| **프리미엄** | 쿨타임 5분, 일일 20회 |

```

┌─────────────────────────────────────┐
```

## 12. 열린 질문 (추후 결정)

1. **창세기 품질 관리**: 부적절한 창세기 필터링 방법?
2. **오브젝트 상한**: maked pool / 세션당 오브젝트 최대 개수?
3. **AI 이미지 생성 비용**: 누가 부담? (시스템 vs 창조자)
4. **픽셀 아트 스타일 가이드**: 일관된 팔레트/스타일 정의 필요
