# 1. 주요 역할 및 개념

## 1.1 창조자 (Creator)

- **정의**: “창조세션”을 생성할 수 있는 권한을 가진 사용자
- **획득 경로**: 유료 재화 구매(또는 특정 조건 달성) 등을 통해 1회성으로 권한 획득
- **주요 권한**:
    - 세션 생성 시 **창세기**(해당 세션의 세계관·규칙)를 입력
    - 세션명, 소개, 기타 설정값 등을 지정

## 1.2 신 (God / Participant)

- **정의**: 창조자가 아닌 일반 참가자
- **주요 권한**:
    - 하나의 세션에 참여하여, 최대 N회(예: 3회)까지 **개입**(프롬프트)을 입력
    - 세션 상황을 지켜보고, 필요하면 액션을 수행(추가적인 조작이나 광고 시청 등은 구현 정책에 따라)

## 1.3 세션 (Session)

- **정의**: 하나의 세계(무대)를 의미하며, 창조자가 만든 **창조세션**과 시스템이 자동으로 만든 **자동세션**으로 구분
- **주요 특징**:
    1. **창조세션**: 창조자의 **창세기**를 기반으로 시작
    2. **자동세션**: 시스템(콘텐츠)이 자동으로 세계관 및 설정을 부여해 시작
- **세션 내 구조**: 도트칸(grid)에 여러 **오브젝트**가 배치되어, “자동진행”과 “개입”을 통해 변화

## 1.4 창세기 (Genesis)

- **정의**: “창조자”가 입력하는 해당 세션의 절대 불변 진리(세계관·컨셉 설명)
- **입력 제한**: 최대 1000자
- **용도**:
    - 세션 전체의 분위기·테마를 정의
    - 이후 “신”의 개입이나 오브젝트 상태 변화 등이 모두 창세기를 기반으로 전개됨

## 1.5 개입 (Intervention)

- **정의**: “신”이 세션에 영향을 미칠 때 입력하는 짧은 프롬프트(문장)
- **입력 제한**: 200자 미만
- **결과**:
    - 시스템(콘텐츠)이 이를 해석하여, 세션 내 **오브젝트** 상태를 바꾸거나 새로운 오브젝트를 탄생시키는 등의 변화를 일으킴
    - 개입이 발생하면, “오브젝트 상태(0~16)”, “maked object 생성” 등으로 이어질 수 있음

## 1.6 액션 (Action)

- **정의**: 개입과는 별도로, 세션 내에서 유저(“신”)가 추가로 수행할 수 있는 행동
- **예시**:
    - 오브젝트 상세 정보 보기
    - 오브젝트를 선택 후 특정 기능(합성, 복제 등)을 요청
    - 광고 시청 후 추가 개입권 획득 등(구현 정책에 따라)
- **중요성**: 각 액션마다 광고 시청 등 별도 조건을 설정할 수 있어, **콘텐츠 내 운영 정책**에 따라 세부적으로 구현

# 2. 화면 (Screen) 구성

## 2.1 도트칸 (Grid) 해상도

- 내부적으로 가상 픽셀 좌표계를 사용 (예: 60×100, 혹은 81×144)
- 실제 기기 해상도와 무관하게, UI 측에서 스케일링하여 표시

## 2.2 오브젝트 배치

- 세션이 시작될 때 **초기 오브젝트**가 화면 위에 무작위로 배치
    - “origin object” + “maked pool”에서 일정 개수를 추출
- 오브젝트 최대 개수는 구현상 제한(예: 1,000개)을 둘 수 있음

---

# 3. 오브젝트 (Object) 구조

## 3.1 오브젝트 종류

1. **origin object**
    - 서버(또는 앱)에 **미리 정의**된 기본 오브젝트
    - 예) 떡갈나무, 바위, 작은 동물, 불꽃 등
2. **maked object**
    - “신”이 개입할 때, 새로운 오브젝트가 **생성**될 확률이 있음
    - 한 번 만들어진 maked object는 **maked pool**에 기록되어, 다른 세션에서도 재활용 가능

## 3.2 오브젝트 상태 (0~16)

- 각 오브젝트는 **최대 17개**(0번~16번)의 상태를 가질 수 있음
- **상태 설명**: 각 상태는 **한 줄**짜리 텍스트로, 해당 상태를 묘사
    - 예) 떡갈나무(0): “초록잎이 무성하게 자란 떡갈나무”
    - 떡갈나무(1): “비에 흠뻑 젖은 떡갈나무”
- 상태 번호가 아직 정의되지 않았다면, 개입이나 자동진행 등에 의해 **새로 생성**될 수 있음

## 3.3 상태 변화

- **개입** 시, 시스템이 개입 프롬프트를 해석하여, 기존 상태를 다른 번호로 바꾸거나,새로운 상태(번호+설명)를 만들어서 그 오브젝트에 적용
- **자동진행** 시에도, 일정 주기에 따라 오브젝트 상태가 다음 단계나 다른 번호로 변경될 수 있음

## 3.4 maked pool

- **정의**: 생성된 maked object(이름, 스프라이트, 이미 정의된 상태들)를 모아두는 저장소
- **역할**: 새로운 세션을 만들 때, 이 풀(pool)에서 여러 오브젝트가 무작위로 선택되어 배치 → 매번 새롭고 예측 불가능한 조합을 형성

# 4. 세션 진행 흐름

## 4.1 세션 생성

1. **창조세션**
    - “창조자”가 **창세기**를 입력하고 세션을 생성
    - 초기 화면에는 “origin object”와 “maked pool” 중 랜덤 추출된 오브젝트가 배치됨
2. **자동세션**
    - 시스템이 주기적으로 자동 생성
    - 기본적인 세계관(또는 간단한 프롬프트)를 바탕으로 시작

## 4.2 자동진행 (Auto Flow)

- 세션은 일정 시간 간격(예: 1시간, 하루 등)으로 자동 업데이트
- 업데이트 시, 시스템이 **현재 상태**를 요약·정리하고, 일부 오브젝트 상태를 바꾸거나, 오브젝트를 제거·추가할 수 있음
- 새 상태가 필요하다고 판단되면, 0~16 범위 내에서 아직 비어있는 상태 번호를 만들고 한 줄짜리 설명을 기록

## 4.3 신의 개입

- 각 “신”은 세션 내에서 최대 N회(예: 3회)까지 개입권을 가짐
- 개입 = 최대 200자 미만의 프롬프트 입력
- 시스템은 해당 프롬프트를 분석하여,
    1. **오브젝트 상태 변경** 또는 **새 상태 생성**
    2. **maked object** 생성(확률적) → “maked pool”에 추가
- 개입 후, 결과(어떤 상태로 바뀌었는지 등)를 세션에 반영

## 4.4 액션

- 개입과 별도로, 세션 내에서 사용자가 수행할 수 있는 추가 조작
    - 예) 특정 오브젝트 정보 보기, 오브젝트 간 합성, 스크린샷 공유 등
    - 구현 정책에 따라 **광고 시청** 등 조건을 붙일 수 있음

# 5. 상세 예시 시나리오

1. **창조자**가 “판타지 숲”이라는 세계관의 **창세기**를 500자 정도로 작성, 창조세션을 개설.
2. **신**(일반 유저)들이 이 세션에 참여. 초기 화면에는 (a) 떡갈나무(0), (b) 버섯(0), (c) 돌멩이(0) 등이 자동 배치됨.
3. **자동진행**(1시간 뒤) → 시스템은 “날씨가 비”라는 설정을 반영, 떡갈나무(0)를 떡갈나무(1) “비에 젖은 떡갈나무” 상태로 변경.
4. **신의 개입**: 유저가 “버섯이 엄청나게 커졌다”고 입력 → 시스템은 버섯(1) 상태를 새로 만들어서 “커다란 버섯”이라 저장, 해당 버섯의 상태를 1로 바꿈. 동시에 새 키워드(“커다란 버섯”)에 따라 **새로운 maked object**(변형된 버섯 스프라이트)가 생성될 수도 있음.
5. 이후 이 **maked object**가 “maked pool”에 저장되어, 다른 세션에서도 “커다란 버섯”이 초기 배치로 등장할 수 있음.

- **신 1**: 로잔 (Rozan)

- **신 3**: 시엘 (Ciel)

창세기는 “끝없이 떠다니는 하늘섬과, 그 위에 자라는 기묘한 생물들을 관찰하는 세계”라는 설정이다.

## 2. 창세기 (창조자: 루카)

루카가 입력한 창세기(일부 발췌):

> “하늘 아래 무수한 섬들이 부유한다. 이 섬마다 고유한 생명체가 깃들어 있고,
> 
> 
> 때로는 서로를 이어주는 구름다리가 생기기도 한다.
> 
> 이 세계의 법칙은 오직 ‘진화’와 ‘변화’를 통해 서로를 인정하는 것이다.
> 
> … 생명체가 비를 맞으면 더욱 기묘한 형태로 자라나며,
> 
> 바람이 강하게 불면 섬을 통째로 흔드는 힘이 생길 수도 있다.”
> 

이 창세기에 따라, 세션이 시작되면 **하늘섬**의 도트 배경이 기본으로 깔린다.

그리고 **origin object**로 준비된 “하늘 풀”, “둥둥 구름바위”, “바람새 알” 등이 배치된다.

각 오브젝트는 상태 0부터 시작한다.

---

## 3. 초기 오브젝트 예시

1. **하늘 풀(0)**
    - 상태(0) 설명: “흰 솜털 뿌리가 달린 작은 풀. 땅에서 조금 떠 있는 듯한 모양이다.”
2. **둥둥 구름바위(0)**
    - 상태(0) 설명: “구름과 바위가 섞인 듯 가벼워 보이는 돌덩이.”
3. **바람새 알(0)**
    - 상태(0) 설명: “크기가 주먹만 한 하얀 알. 살짝 흔들리는 듯한 진동이 느껴진다.”

---

## 4. 다섯 신(참가자)의 개입과 시나리오 전개

### 4.1 첫 번째 개입 (신 1: 로잔)

- **개입 내용**: “섬이 점차 어두워지더니, 하늘에서 푸른 비가 내리기 시작했다.”
- **시스템 반응**:
    1. “푸른 비”라는 키워드를 해석해, “하늘 풀(0)”을 “하늘 풀(1)” 상태로 변화시킴.
        - *새 상태(1) 생성*: “푸른 빗물에 젖은 하늘 풀. 줄기 끝이 파랗게 빛나기 시작한다.”
    2. 새 키워드(“푸른 비”)가 독특하다고 판단, **maked object**: “물방울 정령(0)”을 생성하여 **maked pool**에 추가.
        - “물방울 정령(0)” 상태 설명: “방울 형태의 작은 생명체. 주위 온도를 낮추는 힘을 지닌다.”

### 4.2 두 번째 개입 (신 2: 미오)

- **개입 내용**: “알이 깨지며 작은 바람새가 태어나고, 바람을 따라 춤추듯 날아다닌다.”
- **시스템 반응**:
    1. “바람새 알(0)”이 “바람새 알(1)”로 변화 → *새 상태(1)*: “껍데기가 갈라져, 희미한 날갯짓 소리가 들린다.”
    2. 몇 분 뒤 자동 진행을 통해 알이 완전히 부화, **바람새(0)**라는 오브젝트가 새로 탄생.
        - 바람새(0) 상태 설명: “태어난 지 얼마 안 된 작은 새. 주변 공기를 흔들어 미세한 바람을 만든다.”
    3. “춤추듯 날아다닌다”라는 표현을 바탕으로, 바람새(1) 상태를 추가로 생성해둘 수도 있음.
        - 바람새(1): “깃털에서 바람이 뿜어져 나와, 가까운 구름바위를 끌어당긴다.”

### 4.3 세 번째 개입 (신 3: 시엘)

- **개입 내용**: “하늘섬 중심에 커다란 균열이 생기고, 빛나는 수정 기둥이 드러났다.”
- **시스템 반응**:
    1. 아직 정의되지 않은 오브젝트 “수정 기둥”을 **maked object**로 탄생.
        - “수정 기둥(0)” 상태: “섬의 한가운데서 빛을 뿜는 거대한 결정체. 작은 진동을 일으킨다.”
    2. 기둥이 주변 오브젝트를 반응시키도록, **둥둥 구름바위(0)**를 “둥둥 구름바위(1)”로 업그레이드:
        - 둥둥 구름바위(1): “수정 기둥의 빛을 받으며, 미세하게 파란 기운이 감돈다.”

### 4.4 네 번째 개입 (신 4: 브로니)

- **개입 내용**: “바람새들이 기둥을 맴돌기 시작했고, 기둥이 바람을 흡수해 날카로운 소리를 냈다.”
- **시스템 반응**:
    1. 이미 존재하는 “바람새(0)”를 “바람새(2)”로 점프시킬 수도 있음(중간 상태 1은 만들어둔 상태로 간주).
        - *새 상태(2)*: “수정 기둥을 맴돌며 공명하는 바람새. 깃털 끝이 수정처럼 반짝인다.”
    2. 오브젝트 “수정 기둥(0)”이 “수정 기둥(1)”을 새로 생성하는 확률이 발생.
        - 수정 기둥(1): “바람의 에너지를 흡수해 날카로운 진동을 낸다. 기둥 표면에 금이 가기 시작한다.”

### 4.5 다섯 번째 개입 (신 5: 에란)

- **개입 내용**: “구름 사이에서 거대한 그림자가 나타나더니, 섬 전체를 덮을 듯한 ‘구름 고래’가 서서히 떠올랐다.”
- **시스템 반응**:
    1. 아직 정의되지 않은 오브젝트 “구름 고래”를 **maked object**로 생성 → **maked pool**에 추가.
        - 구름 고래(0): “구름과 물방울로 이루어진 거대한 생명체. 하늘섬을 아가미처럼 빨아들이는 듯한 움직임을 보인다.”
    2. 자동 진행 시, 구름 고래가 하늘섬 상공을 돌며, **하늘 풀(1)**을 “하늘 풀(2)”로 변형:
        - 하늘 풀(2): “구름 고래가 만들어낸 바람에 휘말려, 줄기가 길게 늘어났다. 땅 위가 아니라 공중에서 더 잘 자라는 듯 보인다.”

## 5. 시나리오 요약 & 재미 요소

1. **창조자 루카**가 “하늘섬의 실험실”이라는 독특한 창세기로 세션을 열었다.
2. *5명의 신(로잔, 미오, 시엘, 브로니, 에란)**은 저마다 상상력 넘치는 개입을 통해 새로운 오브젝트(“물방울 정령”, “수정 기둥”, “구름 고래” 등)를 생성하거나, 기존 오브젝트를 새로운 상태로 변화시켰다.
3. **상태(0~16) 시스템**을 통해, 같은 오브젝트라도 상황과 개입에 따라 전혀 다른 설명과 특성을 갖게 되었다.
4. 세션이 자동진행되면서, 섬이 비에 젖고, 알이 부화하며, 기둥이 빛을 뿜고, 구름 고래가 나타나는 등 **끊임없는 변화**가 이어졌다.
5. 새로 생성된 “maked object”들은 **maked pool**에 쌓여, 추후 다른 세션에서 **무작위로 등장**할 수도 있다.
    - 예: 다음 번에 창조자가 또 다른 세계관을 열 때, 이미 만들어둔 “구름 고래(0)”가 초기에 배치될 가능성도 있음.

이런 식으로, **각 신의 개입**은 “하늘섬”이라는 세계에 **다채로운 서사를 불어넣**고, 오브젝트들의 상태가 확장·변형되어 **예측 불가능한 전개**가 펼쳐집니다.

플레이어들은 “내가 만든(개입한) 설정이나 오브젝트”가 시간이 흐름에 따라 어떻게 바뀌는지, 혹은 다른 세션에서 어떻게 재등장하는지를 지켜보며 **방치형**의 재미와 **공동 창작**의 매력을 동시에 느낄 수 있게 됩니다.
